Page layout

Choose between the built-in sign-in page and a page you write yourself.

A page you write yourself runs in the browser of every guest who connects. It may contain JavaScript, and it is served on a public URL. Only the panel operator can reach this form, but if that account is ever compromised the attacker can show any page they like to your customers. Remote scripts, remote styles and framing stay blocked by the server's security policy.

Discard changes

Install the portal on the MikroTik

Until this is done the router keeps serving its own built-in hotspot/login.html, so a guest who joins the SSID sees the stock MikroTik portal and never reaches this panel. The panel can set up the network, the server and the vouchers, but it does not write files to your router — that one step is yours.

Use an address the router can reach - usually the panel's LAN IP, not the address you browse the panel with (a ZeroTier IP or hostname the router cannot route to will fail with "Host is unreachable").

Runs the fetch for you on every registered router and reports the result. Use it if guests see a broken or built-in MikroTik page.

Or do it by hand on each router:

  1. Check where the router keeps its hotspot pages.
    /ip hotspot profile print detail
    The html-directory value is where login.html lives. It is usually hotspot.
  2. Back up the page you are about to replace.
    /file print name=hotspot/login.html
  3. Let the router fetch this panel's redirect page.
    /tool fetch url="{{.RouterLoginURL}}" dst-path=hotspot/login.html mode=http
  4. Let guests reach this panel before they sign in. Without this rule the walled garden blocks the redirect and the guest never gets the login page.
    /ip hotspot walled-garden add server=hotspot1 dst-host={{.PortalHost}} action=allow comment="aircoins login page"
    Replace hotspot1 with your hotspot server name from /ip hotspot print.

You can also manage that walled-garden rule from Network → Walled garden once the router is registered. The same file is downloadable directly at {{.RouterLoginURL}}.
