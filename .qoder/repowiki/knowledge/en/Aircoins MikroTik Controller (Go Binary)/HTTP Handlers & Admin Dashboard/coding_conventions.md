- Each handler file defines a page/form struct embedding the shared `page` base type and implements a `base() *page` method so `render()` can inject CSRF token, flash message, portal name, version, and admin path uniformly.
- REST endpoints follow a uniform shape: a `toAPI*` converter pairs with a typed request struct decoded via `decodeAPIBody`, errors go through `writeAPIError` with a machine-readable `code` field, and device calls use `apiRouterLookup` / `apiRouterLookupDB` to resolve the router before dialing.
- Errors from the RouterOS layer are classified into sentinel errors (`ErrRouterNotFound`, `ErrRouterConflict`, `ErrRouterNoCommand`, `ErrRouterDevice`) and translated into HTTP status codes plus human-friendly hints via `routerErrorHint`.
- Form handling uses a three-step pattern: a `newXxxForm()` constructor with defaults, `xxxFormFromRequest` to populate it from `PostFormValue`, and an `validate(requirePassword bool)` method that populates an `Errors map[string]string` keyed by field name.
- Public vs. authenticated paths are decided centrally by `isPublicPath` after stripping the admin prefix via `trimAdminPath`, keeping the same rule table whether the panel is mounted at `/` or `/admin`.
- Configuration flows through a `Config` struct with a `withDefaults()` method that fills safe defaults (e.g. 300s coin pulse, 12h admin TTL, 12 login attempts/min) rather than trusting zero values.
