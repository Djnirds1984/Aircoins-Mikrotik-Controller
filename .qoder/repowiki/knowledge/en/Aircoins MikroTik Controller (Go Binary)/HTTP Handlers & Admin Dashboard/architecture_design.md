Single Go package `handlers` centered on one `Handler` struct (defined in `handlers.go`) that owns the database handle, compiled `html/template` set, `Config`, logger, per-IP limiter, login guard, traffic window, and full-page portal renderer. `Routes()` builds two front doors: `/` serves the captive portal (with OS probe paths and hotspot redirect entries registered publicly), while `/admin` is mounted via `http.StripPrefix` behind `requireAuth`. All routes are declared in `adminRoutes()`, which also mounts the JSON API under `/api/v1` via `RoutesAPI` in `api.go`. Middleware is layered as `recoverer -> logRequests -> securityHeaders -> csrfGuard -> requireAuth`, with CSRF exempted for `/api/v1/*`, `/portal/*`, and the coin-pulse endpoint. Device access goes through `MikrotikClient` in `mikrotik.go`, which abstracts two transports — binary RouterOS (`mikrotik_ros.go`) and RouterOS v7 REST (`mikrotik_rest.go`) — so handlers never speak either protocol directly. Cross-cutting concerns live in dedicated files: admin session + brute-force guard (`adminauth.go`, `adminmiddleware.go`), captive portal pages (`captive.go`, `portal*.go`), router inventory CRUD (`routers.go`), network/hotspot management (`network.go`, `mikrotik_hotspot*.go`, `mikrotik_network*.go`), vouchers (`vouchers.go`), rates/coin slot (`coin.go`, `rates.go`), sessions (`sessions.go`), settings/tools/icons (`settings.go`, `tools.go`, `icons.go`), and shared template/page helpers (`views.go`).
